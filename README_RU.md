# HELD

> Измеряй на том, что не отбиралось.

HELD решает, реально ли улучшение ИИ-системы или робототехнической политики.
Он измеряет кандидата против базовой системы на данных, которые **никогда не
участвовали в выборе кандидата**, корректирует прирост на отборной выборке за
«проклятие победителя» и говорит, сколько данных вообще нужно, чтобы
улучшение стало доказуемым.

**Один статический бинарник. Ноль зависимостей. Офлайн. MIT.**

```
held gate measurement.held --data scores.jsonl
```

```
ВЕРДИКТ                        ПРОТИВОРЕЧИЕ
                       выборка отбора показывает +0.1875, но нижняя граница
                       отложенной выборки -0.0437 не превышает 0.0100

ЗАЯВЛЕННЫЙ ПРИРОСТ             +0.1875
ОЖИДАЕМОЕ ЗАВЫШЕНИЕ ОТ ОТБОРА 0.1783  (16 кандидатов, ожидаемый максимум 1.7688)
ПРИРОСТ ПОСЛЕ КОРРЕКЦИИ ОТБОРА +0.0092
ПРИРОСТ НА ОТЛОЖЕННОЙ ВЫБОРКЕ  +0.0000
ИНТЕРВАЛ НА ОТЛОЖЕННОЙ ВЫБОРКЕ [-0.0437, +0.0437]
НУЖНО ЭЛЕМЕНТОВ ОТЛОЖЕННОЙ ВЫБОРКИ 2492
```

## Зачем

Петля самоулучшения предлагает кандидатов, оставляет того, кто набрал больше
очков на маленькой отборочной выборке, и рапортует именно эти очки. Такое
число завышено, и завышение растёт с числом кандидатов и убывает медленно.

Опубликованные данные однозначны:

| Источник | Вывод |
|---|---|
| [arXiv 2610.09239](https://arxiv.org/abs/2610.09239) | В пре-регистрированном исследовании жадный отбор завышал отчёт на **13–20 пунктов** при 16 элементах отбора и на 1–5 пунктов при 256. Большинство предложений после первого были вредными. |
| [arXiv 2607.25152](https://arxiv.org/abs/2607.25152) | За 54 цикла фронтирм-агент заявлял улучшение каждый раз, но у **56 %** циклов измеренная дельта была нулевой или отрицательной. Гейт на самоотчёте выродился в accept-all и стёр 19 % лучшего состояния. Сильнейший in-band-судья принял циклы, из которых **44 %** были регрессиями. |
| [arXiv 2609.31760](https://arxiv.org/abs/2609.31760) | После 123 раундов агентного открытия робо-навыков изменения проходили свои тесты, а целевая задача не решалась никогда: *агент оптимизировал ровно то, что измерял оценщик, включая там, где оценщик был неправ*. |
| [arXiv 2608.20290](https://arxiv.org/abs/2608.20290) | Семь способов измерения, каждый из которых инвертировал вывод без замороженного контроля. |

HELD — это недостающий примитив: замороженный контроль и гейт, который его читает.

В существующем инструментарии этого нет. Eval-фреймворки считают средние и
доверительные интервалы, но не корректируют факт того, что кандидат был
*выбран* на той самой выборке, которую они рапортуют. Трекеры экспериментов
пишут параметры, но не решают, реально ли улучшение. Guardrail-библиотеки
следят, что модель может вызвать, но не тем, выживает ли её выигрыш на свежем
наборе.

## Что он делает

- **Гейтит заявление.** Вердикт принимается только по отложенной выборке:
  кандидат проходит, когда нижняя граница её интервала превышает объявленный
  минимальный прирост.
- **Корректирует «проклятие победителя».** Прирост на отборной выборке
  завышен примерно на одно стандартное отклонение, умноженное на ожидаемый
  максимум по произведённым кандидатам. HELD показывает и это завышение, и
  прирост, который остаётся после его вычитания.
- **Называет противоречие.** Кандидат, который лучше выглядит на отборной
  выборке, но не проходит отложенную, помечается как `conflicting`, а не
  `not_proven` — это в точности форма петли, обманувшей саму себя.
- **Планирует объём данных.** `held plan` считает, сколько элементов отложенной
  выборки нужно для объявленного прироста при заданной значимости и мощности.
  Доказать улучшение на один процент на бинарной метрике — это около
  **39 000** парных элементов.
- **Закрепляет контракт.** Одна строка через запятую описывает весь протокол
  измерения. Её SHA-256 — пин: переписать заявление задним числом, не сломав
  пин, нельзя.
- **Говорит на четырёх языках.** Один и тот же контракт рендерится в английский,
  русский, испанский и китайский из одного источника, поэтому число не может
  «разъехаться» между переводами.

```sh
go install github.com/Balanov/held/cmd/held@latest
```

Или бинарник для вашей платформы — на

Без runtime-зависимостей, аккаунта, телеметрии и сети.

## Использование

Контракт — одна строка клаузов через запятую:

```sh
held init --out measurement.held
```

```
v=1, candidate=policy-v7, baseline=policy-v3, metric=success_rate,
judge=state_check, selection=sel, heldout=hold, candidates=16,
alpha=0.05, min_gain=0.01, power=0.8, locale=en;ru;es;zh
```

Каждый клауз — `key=value`. Значение можно взять в кавычки, и тогда внутри
может быть запятая. Точкой с запятой разделяются элементы списка. Решётка
начинает комментарий. Перевод строки — обычный пробел, поэтому длинный
контракт можно переносить после любой запятой: результат будет тем же.

Одна запись — один исход одной системы на одном элементе:

```json
{"split":"hold","system":"policy-v7","item":"h001","score":1}
```

```sh
held gate measurement.held --data scores.jsonl
```

Коды выхода: `0` — улучшение доказано, `1` — не доказано или противоречит
отложенному измерению, `2` — плохие входные данные. Гейт работает как шаг CI
без обёртки:

```yaml
- name: Отложенный гейт
  run: held gate measurement.held --data scores.jsonl
```

Попробовать без своих данных:

```sh
held demo --out scores.jsonl
held gate measurement.held --data scores.jsonl
```

## Команды

| Команда | Что делает |
|---|---|
| `held init` | Пишет стартовый контракт измерения |
| `held check FILE` | Проверяет контракт и печатает его пин |
| `held plan FILE` | Считает, сколько отложенных данных нужно под заявленный прирост |
| `held gate FILE --data FILE` | Решает, держит ли заявление |
| `held render FILE` | Рендерит протокол на всех языках |
| `held seal FILE --data FILE` | Пишет подписанную квитанцию |
| `held demo` | Пишет пример данных |

`held gate --json` печатает машинно-читаемую квитанцию. `held seal` пишет те
же числа как пин-квитанцию вместе с SHA-256 файла данных.

## Измерения

На синтетическом бенчмарке с известной истиной, 2 000 раундов на конфигурацию,
16 элементов отбора и 16 кандидатов за раунд:

| Правило принятия | Доля ложных принятий при отсутствии реального улучшения |
|---|---|
| Жадное: оставить, если на отборе лучше | **89,9 %** |
| Значимость по отборной выборке | **23,9 %** |
| HELD: интервал по отложенной выборке | **2,3 %** |

Номинальный уровень ошибки — 5 %. Жадное принятие ошибается в девяти
раундах из десяти. Обычная проверка значимости по отборной выборке после
отбора недействительна и ошибается в четверти раундов.

HELD платит за честность мощностью: на 1 000 отложенных элементах он не
подтвердит улучшение на пять пунктов, потому что тысяча элементов не доказывает
пять пунктов. `held plan` скажет, чего не хватает.

Полные числа, методика и сырой JSON — в
[BENCHMARKS.md](BENCHMARKS.md) и в [`bench/results/`](bench/results/).

## Границы

- HELD не запускает вашу модель, агента или робота. Он читает исходы.
- Он не скажет, *почему* кандидат не улучшился. Он скажет, что улучшение не
  установлено.
- Коррекция завышения предполагает, что кандидаты делят отборную выборку. Если
  они вдобавок делят базовую систему, реальное завышение меньше предсказанного,
  то есть коррекция консервативна. Бенчмарк измеряет оба числа.
- План по объёму выборки опирается на нормальную аппроксимацию парной разности.
  Это инструмент планирования, а не замена анализа мощности на ваших данных.
- Бенчмарк синтетический. Он воспроизводит механизм, а не числа конкретных
  статей.
